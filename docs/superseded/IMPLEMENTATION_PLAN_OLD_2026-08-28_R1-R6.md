### 0-A. 【치명적】 §7 마지막 줄의 67.4%를 지지하는 측정이 없습니다

초안 §7과 §10은 "주효과 소거 점수 함수 → 67.4% 도달 가능"을 결론의 축으로 씁니다.
`eval_e2_hadamard_decomposition.py:134`에 `compute_zero_alpha_intervention()`이 **이미 구현되어 실행까지 되었으나**, 결과는 다음과 같습니다.

| 항목 | 값 | 출처 |
|:---|---:|:---|
| 기준선 2×2 정답률 | 0.375% | `e2_per_concept_decomposition.csv` `joint_acc` |
| **사영 후 2×2 정답률** | **0.813%** | 같은 파일 `joint_acc_proj` |
| 사영 후 \|α\| | 0.00442 (기준선 0.00781 대비 **43%만 감소**) | `alpha_proj_mean` |
| 사영 후 γ | 0.00061 (기준선 0.00056 대비 +10%) | `gamma_proj_mean` |
| 사영 후 γ > \|α\| 인 개념 | **0 / 33** | 위 두 열로 계산 |

즉 현재 구현은 **α를 0으로 만들지 못합니다**(43% 감소). 사영 후에도 |α|가 γ의 7.2배이므로 명제 1에 의해 정답률이 0 근처에 머무는 것이 **정상**이며, 이 측정은 초안의 예측을 반증하지도 지지하지도 않습니다. 함수 이름 `compute_zero_alpha_intervention`이 실제 동작(부분 감쇠)과 어긋나는 것이 오해의 원인입니다.

> **함의**: R6은 "선택적 격상 항목"이 아니라 **차단 요인**입니다. 67.4%는 현재 어떤 실측으로도 뒷받침되지 않습니다.

## 5. R6 — 주효과 소거 실험 (차단으로 승격, 반나절)

§0-A에 따라 **기존 구현으로는 §7의 예측을 검증할 수 없습니다.** 세 단계로 나눕니다.

### 5-1. 현재 구현의 한계 확정 (30분)
`compute_zero_alpha_intervention()`이 왜 |α|를 43%만 줄이는지 규명합니다. 가설: 전역 이미지 평균 `mu_I_global` 하나로 사영하는데(`eval_e2_hadamard_decomposition.py:418`), α = μ_I·v에서 **객체별 μ_I가 전역 평균과 다르기** 때문에 잔차가 남습니다.
→ 객체별 μ_I로 사영하도록 바꾸고 |α|가 얼마나 더 줄어드는지 측정합니다. 이것만으로 예측에 근접할 가능성이 있습니다.

### 5-2. 양측 주효과 소거 구현 (2–3시간)
초안 R6이 요구하는 것은 α와 β **둘 다** 소거입니다. 현재 구현은 텍스트 측만 건드립니다.
```
v_perp = v − (v·μ̂_I) μ̂_I        # α_W → 0   (현재 구현, 단 μ_I를 객체별로)
u_perp = u − (u·μ̂_T) μ̂_T        # β_W → 0   (미구현)
```
두 사영 후 α, β, γ, Δ를 재계산합니다. 함수명을 `compute_main_effect_ablation`으로 바꾸고, 사영 후 |α|·|β|가 실제로 0에 수렴했는지 **assert로 검증**한 뒤에야 정답률을 보고하도록 만드십시오. §0-A의 오독은 이 검증이 없어서 발생했습니다.

### 5-3. 예측 대조 (30분)
- **예측**: α_W ≈ 0, β_W ≈ 0, 2×2 정답률 ≈ 67.4% (clean 부분집합 68.0%)
- 근거: `pair_gamma_gt_zero_rate_all = 67.43%` — 주효과가 0이면 성공 조건이 γ > 0으로 완화되므로 γ>0인 쌍 비율이 곧 정답률입니다.
- 일치하면 §3의 대수가 개입 결과를 사전 예측한 것이 되어 논문 성격이 "진단"에서 "진단+검증된 예측"으로 바뀝니다.
- 어긋나면 그 격차가 §3.4 가법 모델이 깨지는 지점을 정량화하므로 §9.3 한계에 씁니다. 초안이 쓴 대로 **어느 쪽이든 손해가 없습니다.**

⚠️ **경계**: 사영은 개념별로 다른 W를 쓰는 것과 등가입니다. 초안 §7이 스스로 지적했듯 실제 검색기는 단일 W를 씁니다. 결과를 "물리적 상한"이 아니라 **"W=I 근방에서 주효과만 소거했을 때의 도달점"**으로 서술해야 하며, 이 단서를 결과 표 캡션에 함께 넣으십시오.

## 6. R5 — 신호 성분 비율 (비차단, 1시간)

**초안의 "15분, 기존 CSV로 끝남"은 성립하지 않습니다.** 필요한 양이 기존 산출물에 없습니다.

`eval_e2_sanity_check_and_grounding.py:175`는 `d_I = delta_I / ‖delta_I‖`를 **쌍마다** 계산합니다. 즉 기존 `cos_align_mean = 0.029`는 **인스턴스 방향 정렬**이며, R5가 요구하는 **개념 평균 방향** d_I^(o) = normalize(mean_pairs δ_I)는 계산된 적이 없습니다. 이 구분이 §6.5 서술의 핵심(0.217 대 0.029의 7배 격차)이므로 혼동하면 안 됩니다.

**작업**: 같은 파일의 개념 루프(약 171–190행)에 추가합니다.
```python
d_I_c = delta_I.mean(0); d_I_c /= np.linalg.norm(d_I_c) + 1e-9   # 개념 평균 방향
d_T_c = delta_T.mean(0); d_T_c /= np.linalg.norm(d_T_c) + 1e-9
a_I = delta_I @ d_I_c          # 신호 성분
a_T = delta_T @ d_T_c
concept_row.update({
    "a_I_mean": float(a_I.mean()), "a_T_mean": float(a_T.mean()),
    "signal_ratio_I": float(a_I.mean() / s_I_c.mean()),
    "signal_ratio_T": float(a_T.mean() / s_T_c.mean()),
    "cos_concept_dirs": float(d_I_c @ d_T_c),          # 프로브 정렬도 0.217과 대조
})
```
`cos_concept_dirs`를 함께 저장하는 것이 중요합니다 — 이 값이 0.217에 가까우면 §6.5의 "두 정렬도는 서로 다른 양"이라는 설명이 **직접 입증**됩니다.

**초안 예상값**: `a_I/‖δ_I‖ ≈ 0.33`, `a_T/‖δ_T‖ ≈ 0.48`. 크게 벗어나면 §6.5를 다시 써야 합니다.

**비용**: 이미지 재인코딩이 필요합니다(캐시 미사용, §8 참조). ViT-B/32로 2,714장이므로 GPU에서 1–2분입니다.
