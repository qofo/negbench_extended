## II-1. E1 이미지 프로브 29.06% — 우연 이하 ✅ **완료 (2026-08-29)**

**진단 확정.** 원인은 라벨이 아니라 **폴드 분할**이었다. `eval_unary_mechanistic_analysis.py`의
`fit_linear_probe`가 `StratifiedKFold(5)`를 썼고, `X_pos[i]`와 `X_neg[i]`는 같은 장면의 counterfactual 쌍이다.
분할이 쌍을 가르면 거의 동일한 두 벡터가 서로 반대 라벨을 달고 train/test로 나뉘므로, 장면을 외운 프로브가
남겨진 쪽에 **쌍둥이의 라벨**을 붙인다. 우연 이하는 잡음이 아니라 체계적 반전이다.

## II-2. 비전 절제 `zero` 조건 = 정확히 100.00% ✅ **완료 (2026-08-29)**

**진단 확정.** 두 사실이 겹친 결과였다.

1. `torch.argmax`는 동률일 때 **가장 낮은 인덱스**를 반환한다.
2. `COCO_val_mcq_llama3.1_rephrased.csv` **5,914행의 `correct_answer`가 전부 0이다.** 선택지를 섞지 않은
   데이터셋이며 `caption_0`이 항상 정답이다.

Cosine·Weighted Cosine·Bilinear는 모두 이미지 벡터에 대해 선형이고 선택지별 편향이 없으므로, 이미지를
0으로 만들면 네 점수가 완전히 같아진다(**동률률 실측 100.00%**). 순위를 전혀 만들지 못한 헤드가
정확히 100%로 기록된 이유다. 코드 수정 전에 `np.bincount(targets) = [5914]`와 헤드별 동률률로 확인하였다.

**조치 완료.**

| | |
|---|---|
| `scoring_heads.predict_with_tie_report` | 신설. 동률을 시드 고정 무작위로 깨고 `tie_mask`를 함께 반환 |
| `eval_vision_ablation_shortcut.py` | 조건별 `tie_rate`·`n_tied`·`tie_warning`을 요약 JSON에 기록, 콘솔에도 경고 출력 |
| `eval_scoring_heads.py`, `eval_text_ablation_shortcut.py` | argmax 3곳을 동일 헬퍼로 교체(예방적) |
| 회귀 테스트 | `TestTieAwarePrediction` 6건 (52 passed) |

**결과.**

|헤드|zero 이전|zero 이후|동률률|
|---|--:|--:|--:|
|Cosine|100.00|**23.49**|100.00%|
|Weighted Cosine|100.00|**23.49**|100.00%|

값도 재실행 전후로 완전히 동일하다.** 즉 이 표에서 동률의 영향을 받은 칸은 위 세 칸뿐이다.

**부수 발견 — Bilinear의 의존 방식.** 낙폭이 zero −51.17, gaussian −43.90인데 shuffle은 −5.16에 그친다.
즉 **"실제 CLIP 이미지 임베딩이 존재한다"에는 강하게 의존하지만 "그것이 맞는 이미지다"에는 약하게 의존한다.**

`mcq.py:111,276`에도 같은 argmax가 있다. 현재 데이터에서 동률이 관측되지 않았으므로 급하지 않으나,
동일 헬퍼로 통일하는 것이 맞다(A3 스캐폴드 작업에 포함).

## II-3. 플라시보 오염 — clean 개념 재산출 ✅ **완료 (2026-08-29)**

**계획 정정 — 판정 기준 자체가 표본 수를 무시하고 있었다.** 계획은 "PASS 13개만 추려 재실행"이었으나,

|---|---:|---:|
